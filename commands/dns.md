# DNS (노드)

## 노드가 실제로 쓰는 DNS 서버 확인

```bash
ls -l /etc/resolv.conf; cat /etc/resolv.conf
```

- **언제**: 노드나 Pod에서 DNS가 안 될 때 가장 먼저. nameserver와 search 도메인을 확인한다
- **주의**: `ls -l`로 심볼릭 링크인지, 언제 다시 생성됐는지(수정 시각) 같이 본다. 첫 줄 주석(`# Generated by NetworkManager`)으로 누가 관리하는 파일인지 알 수 있고, 직접 고쳐도 그 서비스가 덮어쓴다
- **주의**: `search` 줄에 IP 주소가 있으면 설정 실수다. 보통 보조 DNS를 search 도메인 칸에 잘못 넣은 경우다. 이러면 nameserver가 하나뿐이라 예비 서버가 없고, 모든 이름 뒤에 그 IP를 붙인 쓸모없는 질의가 나간다
- **주의**: Kubernetes에서는 노드의 search 도메인이 Pod의 resolv.conf에도 그대로 붙는다
- **연관**: NetworkManager 쪽 원래 설정은 `nmcli -g ipv4.dns,ipv4.dns-search con show <connection>`

## NetworkManager 연결의 DNS 설정 확인

```bash
nmcli -t -f NAME,DEVICE con show --active
nmcli -g ipv4.method,ipv4.dns,ipv4.dns-search,ipv4.ignore-auto-dns con show <connection>
```

- **언제**: resolv.conf가 왜 그렇게 생성됐는지 원래 설정을 볼 때
- **주의**: `-t`는 콜론으로 구분한 짧은 출력, `-f`는 보여줄 열을 고른다. `-g`는 지정한 값만 줄마다 하나씩 뽑는다
- **주의**: `ipv4.dns`는 nameserver, `ipv4.dns-search`는 search 도메인이다. `ignore-auto-dns`가 no면 DHCP로 받은 DNS도 섞인다
- **연관**: RHEL 8 이하에서는 같은 내용이 `/etc/sysconfig/network-scripts/ifcfg-<device>`의 `DNS1`, `DNS2`, `DOMAIN`에 있다. `grep -H -iE 'DNS|DOMAIN' /etc/sysconfig/network-scripts/ifcfg-*`

## 특정 목적지로 가는 경로 확인

```bash
ip route get <ip>
```

- **언제**: 업스트림 DNS나 외부 서버로 패킷이 어느 인터페이스, 어느 게이트웨이로 나가는지 볼 때
- **주의**: 실제 패킷을 보내지 않고 라우팅 테이블에서 고른 결과만 보여준다. `src`가 이 경로로 나갈 때 쓰는 출발지 IP다

## dig 없이 DNS 응답률 측정

```bash
python3 - <<'PY'
import socket, struct, random, time
server, name, n = "<dns-server>", "<name>", 120
ok = fail = 0; lat = []
for i in range(n):
    q = struct.pack(">HHHHHH", random.randint(0, 65535), 0x0100, 1, 0, 0, 0) \
        + b"".join(bytes([len(p)]) + p.encode() for p in name.split(".")) + b"\0" + struct.pack(">HH", 1, 1)
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); s.settimeout(2); t = time.time()
    s.sendto(q, (server, 53))
    try:
        d, _ = s.recvfrom(4096); ok += 1; lat.append(time.time() - t)
    except Exception:
        fail += 1; print("timeout", time.strftime("%H:%M:%S"))
    s.close(); time.sleep(0.4)
lat.sort(); print("ok=%d fail=%d p50=%.0fms max=%.0fms" % (ok, fail, lat[len(lat)//2]*1000, lat[-1]*1000))
PY
```

- **언제**: 노드에 dig, nslookup이 없을 때(bind-utils 미설치) DNS 서버가 응답하는지, 간헐적으로 응답을 놓치는지 측정할 때
- **주의**: 표준 라이브러리만 쓰는 UDP DNS 질의(A 레코드)다. 응답이 오기만 하면 성공으로 센다. NXDOMAIN도 응답이 온 것이므로 성공이다
- **주의**: 한 번 질의해서 성공하는 것과 계속 성공하는 것은 다르다. 간헐 장애는 여러 번 반복해야 보인다. `n`과 `sleep` 간격을 조절한다
- **주의**: `settimeout(2)`보다 늦은 응답은 실패로 센다

## resolv.conf 변경 이력 보기

```bash
sudo journalctl -u NetworkManager --since '<since>' --until '<until>' --no-pager | grep -iE 'dns|dhcp|resolv'
```

- **언제**: resolv.conf가 언제, 무엇 때문에 다시 생성됐는지 따라갈 때
- **주의**: 시간 범위 지정과 `--no-pager`는 [systemd](systemd.md#서비스-로그를-시간-범위로-잘라내기)와 같다
