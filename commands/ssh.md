# SSH

## 제어 소켓으로 접속 재사용 (master 연결)

```bash
ssh -f -N -M -S /tmp/<name>.sock -o ControlPersist=1h <user>@<host> -p <port>
```

- **언제**: 비밀번호·OTP 인증을 한 번만 하고, 이후 여러 명령이나 스크립트가 같은 연결을 재사용하게 할 때
- **주의**: SSH 연결 멀티플렉싱이다. 인증된 통로를 소켓 파일로 노출해 두고, 이후 접속은 이 소켓을 통해 인증 없이 붙는다
- **주의**: `-M` = master 모드(소켓을 만드는 쪽), `-S` = 소켓 파일 경로, `-f` = 인증 후 백그라운드로 내려감, `-N` = 원격 명령 없이 연결만 유지, `ControlPersist=1h` = 마지막 사용 후 1시간 동안 유지
- **주의**: 소켓 파일 권한이 곧 접속 권한이다. 다른 사용자가 읽을 수 있는 경로에 두지 않는다
- **연관**: 상태 확인 `ssh -S /tmp/<name>.sock -O check <user>@<host>`, 종료 `ssh -S /tmp/<name>.sock -O exit <user>@<host>`

## 제어 소켓으로 원격 명령 실행

```bash
ssh -S /tmp/<name>.sock -p <port> <user>@<host> '<command>'
```

- **언제**: master 연결이 떠 있는 상태에서 인증 없이 원격 명령을 실행할 때
- **주의**: 원격 명령은 작은따옴표로 감싸야 로컬 셸이 `$변수`나 `|`를 먼저 해석하지 않는다
- **주의**: zsh에서는 `S="ssh -S ..."` 처럼 변수에 담아 `$S '<command>'`로 쓰면 변수 전체가 명령 이름 하나로 취급돼 `no such file or directory`가 난다. 그대로 적거나 함수·alias로 만든다
- **주의**: 원격 명령이 멈추면 로컬도 같이 멈춘다. 오래 걸릴 수 있는 명령은 원격에서 `timeout <초>`로 감싼다

## 떠 있는 제어 소켓과 접속 대상 매핑 확인

```bash
ps -ef | grep '[s]sh .*-S '
```

- **언제**: `/tmp`에 소켓이 여러 개 있을 때 어느 소켓이 어느 서버로 연결된 것인지 볼 때
- **주의**: `[s]sh`는 grep 자신이 결과에 걸리지 않게 하는 방법이다(정규식 `[s]`는 s 한 글자와 맞지만 grep 명령줄의 문자열 `[s]sh`와는 안 맞는다)
- **주의**: 소켓 이름만 보고 판단하지 말고, 붙은 뒤 첫 명령으로 `hostname`을 찍어 대상 서버가 맞는지 확인한다
